## 已完成验证

- 干净 Python 3.11.10 虚拟环境安装 wheel，在源码目录之外、未设置 PYTHONPATH 的情况下通过 96 项 Python 自动化测试：通用字段映射、来源与推理认证隔离、同源取数、旧基线保留、请求一致性、JSON/SSE、结构化断言、导入导出、评论锚点、失败/取消/中断、凭据脱敏、升级互斥等。
- 安装包的浏览器实际操作通过：导入 JSON → 创建候选 → 行内评论 → 复制交接 → 本地 Agent 子进程回复 → 创建场景 → 两轮成对 HTTP replay → 查看断言与响应 → 继续追问旧响应 → 刷新保留记录。共保存 3 条 review 和 1 条 Agent 回复。
- 浏览器向本地 HTTP 替身发送了 4 次请求，断言依次为未通过、通过、通过、通过；首屏仍显示历史中有 1 次未通过。追问保留旧响应快照且不新增运行，点击追问不会覆盖未提交的草稿。这用于验证工具机制，不代表真实模型改进。
- 页面运行错误为零；检查了桌面、移动端以及浅色/深色布局。
- wheel / sdist 可构建，wheel 由 sdist 构建；两包均通过 Twine 元数据检查。独立安装后的 CLI、GUI 资源、配套 skill、离线更新说明及浏览器流程可用。
- 独立公开内容检查未发现个人绝对路径、私有服务域名、原始工单/日志 ID 或实际凭据。测试输入与 demo 为人工构造。敏感 header 的多值与名值对形式已补脱敏回归。
- 公开源码、文档、skill、测试与新构建的 wheel / sdist 已检查：没有内置特定组织的数据源名称、接口路径或记录 ID 规则；来源通过通用格式与用户配置的映射接入。
- macOS / Linux 与 Python 3.11 / 3.13 的 GitHub CI 检查测试与安装包；实际运行状态见仓库 Actions。
- 后续用用户提供的对话定位到一份实际请求导出，核对字段映射后，以原模型和日志中可恢复的全部请求参数完成 11 次真实 replay，工具调用断言均通过。历史失败在这些回放中未复现；提示词未修改，不能据此宣称修复或稳定。原始 HTTP 请求体未保存，因此来源仍标为从日志重建。私有证据仅保存在本地工作区，不进入源码或安装包。

## 本轮终检修复

- 凭据保护：拒绝通过候选或场景 patch 写入凭据，包括先写入再移除的中间操作；拒绝来源 URL 和路径模板中的凭据查询参数。来源用户名不再参与全局文本替换，避免损坏 `user` 角色等正常内容。
- 数据完整性：导入实验包前校验实际使用的结构和引用关系；无效包不会污染实验列表。模型返回内容过大时记录明确的错误并停止该批次，不再长期显示运行中。现有本地预览实验可导入新版本，原文件未改变。
- 审阅证据：汇总保留全部历史失败；已保存评论的追问引用原快照，普通过期草稿仍需重新核对。追问不会覆盖正在编辑的草稿。
- Agent 退出：清理所属进程组后再发布终态；真实独立 CLI 成功、失败退出及忽略终止信号的子进程回归通过。macOS 短暂权限竞态采用有界重试，持续失败会明确报错。

复现命令见 README 的 Development checks。构建文件位于本地 `dist/`，该目录不纳入 Git。

## 版本发布与本地更新

与 Quarry 一致，main 上的提交由 Semantic Release 自动递增版本、生成 changelog 和 GitHub Release，并显式派发 PyPI 发布 workflow。发布 workflow 使用确定的 tag，先对该 tag 运行 CI，再构建 UI 和 Python 发行包，核对包版本与 tag 后发布。

首次发布需要在 PyPI 为 `ablation-workbench` 配置 GitHub trusted publisher：仓库 `yiminspace/ablation`、workflow `release.yml`、environment `pypi`。GitHub 中需存在对应 environment。后续正常发布不需要预览版开关或人工输入确认文字。

GUI 后台检查 PyPI，检查结果缓存 24 小时；发现新版后显示当前/最新版本、升级命令和发布说明。用户执行升级命令后重新启动 GUI。源码或 editable 安装不检查注册表，`ABLATION_UPDATE_CHECK=0` 可关闭检查。本机若仍绑定本地源码安装，需要在首个线上发行版可用后改为从 PyPI 安装。
