# Ablation

直接使用已安装的 `ablation` CLI，通过 `ablation --help` 和相应子命令帮助查看当前参数。CLI 负责实验、回放、对比和审阅；Agent 负责解释问题、提出修改并解读证据。英文指引见[英文说明](https://github.com/yiminspace/ablation/blob/main/skills/ablation/SKILL.md)。

## 选择证据

复用对话中已经确定的实验、日志链接、录制引用或文件，不要求用户重复说出数据源工具名称。已导入的实验有固定基线，应继续该实验，不重新获取基线。仍有多个合理来源时，先消除歧义再运行。

输入是对话链接时，通过可用的对话读取工具定位底层请求文件或日志引用。聊天记录或摘要只是上下文，不是原始模型请求：导入前选定相关模型调用，核对输入、指令、工具、参数与回放目标。找不到原始证据时，明确说明缺少什么，不把聊天记录当作忠实的回放来源。

支持请求 JSON、导出的日志和 HTTP 录制，显式选择 `request`、`log` 或 `capture` 格式。来源结构需要映射时，使用已配置 profile 的 JSON Pointer；路径相对原始来源根节点，缺失字段属于错误。创建映射前查看 `ablation config profile --help`。

远程获取需要显式指定来源 base URL，并提供同 origin 的 JSON URL，或通过已配置路径模板解析的引用。网页分享链接可能需要先用已有工具导出 JSON。来源凭证与推理凭证分开，配置只保存环境变量名称，不保存密钥值。不猜测端点地址，也不假定来源环境与回放环境相同。

检查规范化说明和来源到请求的 diff。还原后的日志不等于原始网络请求。除已声明的修改外，保留完整工具 schema 和所有请求字段。

## 设计并运行实验

说明预期行为和最小合理提示词修改，保存候选及修改理由。区分候选提示词修改、场景输入修改与评估检查。人工构造场景必须用通俗语言准确说明改了哪些事实、为什么修改，不能将其表述为线上实际发生的事件。

候选说明写两句或两个短段：先交代问题和预期改善，再说明概念上的代码修改位置与影响。用 `[位置说明](https://github.com/OWNER/REPO/blob/COMMIT/path#Lx-Ly)` 链接核实过的 GitHub 源码位置，不在正文中罗列文件名。核实仓库、版本和行号；判断影响范围前，先区分客户端提供的工具字段、后端定义与后端转换。只有证据支持时才描述参数或客户端影响，未查清的来源和落点标为“待确认”。通过 `--rationale` 保存；安装版本支持时，也可用 `--rationale-file` 读取多行 UTF-8 说明。GUI 在 diff 下的候选说明中显示源码链接，无需单独的 Check 视图。

在相同场景和 profile 下运行可比较的基线与候选请求，按问题需要控制重复次数。断言必须明确检查实际输出；没有检查即未评分，网络失败不属于行为失败。避免仅为通过某个例子，就写入包含该测试答案或下游实现专属标签的规则。

回放前必须配置目标服务的请求追踪与日志关联；交付前核对每次回放对应的日志链接。关联失败须明确标记证据不完整并说明原因，不能将模型调用成功等同于日志证据齐全。

GUI 是人的界面，用于查看 diff 和撰写审阅评论；CLI 是 LLM 的界面，所有实验操作、证据读取、结果分析、统计、断言、diff 和审阅回复都通过 CLI 完成。通过 CLI 启动 GUI，并将地址交给用户；通过 CLI 状态确认启动，不检查浏览器。人的审阅评论也通过 CLI 读取和回复。CLI 缺少所需信息时，报告接口缺口，不转用 GUI 自动化或读取网页。只有另行明确要求测试 GUI 本身时，才检查浏览器界面。

解释观察到的行为与不确定性；单例重复不能证明普遍可靠。模型返回的工具调用只是记录下来的证据，不会被执行，也不能证明现实中的操作结果。

## 审阅循环

审阅交接包含实验 ID、review ID、被审阅的候选与场景、锚定原文片段、用户评论和意图。复用这些 ID 和明确指定的工作区，让回复写回已有 GUI。

- `comment` 意图表示解释或调查。追加线程回复，不要仅为解释修改原因就创建候选或回放。预期操作不明确时，在审阅中提问。
- `changes` 意图允许执行所请求的实验修改和有限次数的重跑。保留旧候选并创建下一个，说明哪些产物可以确认结果。
- 复制到聊天的交接，使用其中提供的回复命令保存回答。自动 runner 调用时，直接返回最终回答，由 runner 保存。

打开 GUI 或保存审阅不会启动 Agent。自动派发依赖已配置的本地 Agent runner，不能保证唤醒已有桌面聊天。否则，将审阅复制到当前对话。

候选始终是实验产物。只有用户要求时，才把补丁应用到业务仓库。升级工具会保留实验数据，不会安装或同步 skill。
