# 中文使用说明

直接使用安装后的 `ablation` CLI；通过 `ablation --help` 和子命令帮助查看当前参数。用户说“用 ablation 优化这里”时，从对话中已有的实验、日志链接、录制引用或文件提取输入，不要求重复说出数据源工具。

输入是对话链接时，先通过可用的对话读取工具定位原始请求文件或日志引用，再选定要回放的模型调用，核对输入、指令、工具、参数与目标连接。聊天记录或摘要只是定位线索，不能当作完整请求；找不到原始证据时明确说明缺少什么。

已有实验沿用固定基线。支持请求 JSON、导出的日志与 HTTP 记录，显式选择 `request`、`log` 或 `capture` 格式。不同来源结构用 profile 的 JSON Pointer 映射；路径相对原始记录根节点，缺失字段会报错。配置前查看 `ablation config profile --help`。

远程来源必须显式配置 source base URL；输入可以是同 origin 的 JSON URL，或由路径模板解析的记录引用。网页分享链接若不是 JSON 接口，先用已有工具导出 JSON。来源查询和模型推理的地址、凭证分别配置，配置里只保存环境变量名称，不猜测端点或环境。

先检查日志到请求的还原说明。原始证据、还原后的请求、候选提示词、测试输入和评判规则分别保存。人工构造场景必须说明改了哪些事实，以及为什么能够代表要验证的情况。工具参数与完整 schema 只改已声明的部分。

给候选写清修改理由，用相同输入条件对比基线与候选，控制运行次数。没有判断规则即未评分；网络错误不能算模型行为失败。避免把某个测试答案或下游专属标签写进通用提示词。单例重复不等于跨场景稳定。

在 GUI 展示数据来源、prompt、输入、实际 request、response 和判断规则的 diff，并区分真实结果、合成示例与尚未验证。模型返回的工具调用不会由工具执行，也不能证明外部系统中的实际操作成功。

评论携带实验 ID、review ID、审阅版本、位置和原文片段。`comment` 是解释或追问，只追加回复；`changes` 才根据用户要求产生新候选并验证。复制到聊天的 review 使用其提供的回复命令写回 GUI；自动 runner 调用时直接返回最终解释，由 runner 保存。始终使用对应工作区，保留旧版本和已有评论。

自动交接通过事先配置的本地 Agent 执行，不能假定可以唤醒当前桌面聊天。也可以始终复制评论到当前对话。只有用户要求时才把实验候选应用到业务仓库。升级工具不安装或同步 skill。
